## Общее описание

Прототип слоя доступа к данным для веб-приложения. Данные хранятся
только в памяти программы (на диск ничего не записывается) в виде
кортежей. Реализован первый этап задания:

- три таблицы по ER-диаграмме: `Agent`, `Command`, `Result`;
- для каждой таблицы: создание, удаление, получение всех записей,
  редактирование (12 операций);
- выборка по формуле реляционной алгебры (13-я операция);
- интерактивный режим REPL.

## Таблицы и их поля

Поля взяты с ER-диаграммы (рис. 13). Чёрная точка на диаграмме —
ключевое поле, белая — обычное.

### Agent — агент (тот, кто отправляет команды)

| Поле | Тип | Смысл |
|---|---|---|
| `key` | int | Уникальный номер агента (первичный ключ) |
| `timestamp` | int | Время создания в секундах (Unix-время) |

### Command — команда, отправленная агентом

| Поле | Тип | Смысл |
|---|---|---|
| `key` | int | Уникальный номер команды (первичный ключ) |
| `timestamp` | int | Время создания в секундах |
| `argument` | str | Аргумент команды |
| `agent` | int | Номер агента-отправителя (ссылка на `Agent.key`) |
| `description` | str | Описание команды |
| `tags` | str | Теги команды |
| `processing` | int | Признак обработки: 0 — нет, 1 — да |

### Result — результат выполнения команды

| Поле | Тип | Смысл |
|---|---|---|
| `key` | int | Уникальный номер результата (первичный ключ) |
| `timestamp` | int | Время получения результата в секундах |
| `output` | str | Вывод команды |
| `state` | str | Состояние, например `ok` или `error` |
| `failure` | str | Текст ошибки, если была |
| `command` | int | Номер команды (ссылка на `Command.key`) |
| `cache_hit` | int | Взят ли результат из кэша: 0 — нет, 1 — да |
| `duration` | int | Время выполнения в секундах |

Связи: один агент — много команд; одна команда — много результатов.
Поэтому нельзя удалить агента, у которого есть команды, и команду,
у которой есть результаты.

## Формула из пункта 3 (что она значит)

```text
π C.tags, R.cache_hit ( ( σ C.timestamp ≥ now − 6 min (C) ) ⟕ C.key = R.command R )
```

Здесь `C` — таблица Command, `R` — таблица Result. Формула читается
изнутри наружу, это три обычных действия:

| Шаг | Символ | Что делает | На языке Python |
|---|---|---|---|
| 1 | `σ` (сигма, отбор) | Оставить команды, у которых `timestamp` не старше 6 минут от `now` | `if command.timestamp >= now - 360` |
| 2 | `⟕` (левое внешнее соединение) | К каждой такой команде подставить её результаты по условию `C.key = R.command`. Если результатов нет, команда всё равно остаётся, а вместо результата — «пусто» (`None`) | вложенный цикл по `results` |
| 3 | `π` (пи, проекция) | Из каждой пары оставить только два поля: `tags` команды и `cache_hit` результата | `(command.tags, result.cache_hit)` |

Итог — список пар `(tags, cache_hit)`. Это реализовано в методе
`get_recent_cache`. В PDF символ `⟕` из-за шрифта выглядит похоже
на `⋈`, но в тексте документа стоит именно `⟕` (U+27D5) — левое
внешнее соединение.

## Почему так устроен код

- **`NamedTuple`** — это обычный кортеж, у элементов которого есть
  имена. Задание требует хранить записи кортежами; `NamedTuple` даёт
  писать `command.tags` вместо `command[5]`. Проверить можно так:
  `isinstance(Agent(1, 2), tuple)` возвращает `True`.
- **`DataModel`** — класс для удобства: держит три списка в одном
  объекте, чтобы не передавать их в каждую функцию отдельно.
- **Сторонние библиотеки не используются.** Импортируются только
  `json` (разбор аргументов и печать ответа), `time` (текущее время)
  и `typing.NamedTuple` — всё это входит в состав Python.
- **Аннотации типов** стоят у полей таблиц, у параметров и
  возвращаемых значений всех методов (`-> Agent`, `-> list[Command]`).
  Все поля таблиц — `int` или `str`, поэтому новые значения полей в
  методах `update_*` имеют тип `int | str`.
- **Docstring** в едином формате: назначение, затем
  `параметр: пример -- описание`, затем `return имя: пример`.
- **Ошибки:** `KeyError` — запись с таким ключом не найдена;
  `ValueError` — нарушено правило (ключ занят, есть связанные записи,
  попытка изменить `key`); `TypeError` — переданы не те поля.

## Аудит методов класса `DataModel`

| Метод | Что получает | Что возвращает | Ошибка |
|---|---|---|---|
| `create_agent(key, timestamp)` | `1, 2000000000` | `Agent(key=1, timestamp=2000000000)` | `ValueError` — ключ занят |
| `delete_agent(key)` | `1` | удалённый `Agent` | `KeyError` — нет ключа; `ValueError` — есть команды |
| `get_agents()` | — | `[Agent(...), ...]` | — |
| `update_agent(key, **changes)` | `1, timestamp=2000000001` | обновлённый `Agent` | `KeyError` — нет ключа; `ValueError` — смена `key` |
| `create_command(**fields)` | 7 полей по именам | `Command(key=10, ...)` | `ValueError` — ключ занят; `KeyError` — нет агента; `TypeError` — не те поля |
| `delete_command(key)` | `10` | удалённый `Command` | `KeyError` — нет ключа; `ValueError` — есть результаты |
| `get_commands()` | — | `[Command(...), ...]` | — |
| `update_command(key, **changes)` | `10, processing=1` | обновлённый `Command` | `KeyError` — нет ключа или агента; `ValueError` — смена `key` |
| `create_result(**fields)` | 8 полей по именам | `Result(key=100, ...)` | `ValueError` — ключ занят; `KeyError` — нет команды; `TypeError` — не те поля |
| `delete_result(key)` | `100` | удалённый `Result` | `KeyError` — нет ключа |
| `get_results()` | — | `[Result(...), ...]` | — |
| `update_result(key, **changes)` | `100, duration=30` | обновлённый `Result` | `KeyError` — нет ключа или команды; `ValueError` — смена `key` |
| `get_recent_cache(now=None)` | `2000000060` (или ничего — текущее время) | `[("demo", 1), ("none", None)]` | — |

Вспомогательные методы (с подчёркиванием, снаружи не вызываются):

| Метод | Назначение |
|---|---|
| `_find(rows, key)` | вернуть индекс строки по ключу или `KeyError` |
| `_check_free(rows, key)` | `ValueError`, если ключ уже занят |
| `_update(rows, key, changes)` | заменить строку новой с изменёнными полями |

Функции вне класса:

| Функция | Назначение |
|---|---|
| `to_json(value)` | превратить кортежи в словари для вывода JSON |
| `run_line(model, line)` | разобрать строку REPL и вызвать метод модели |
| `main()` | цикл интерактивного режима |

## Формат команд в REPL

```text
имя_операции {"поле": значение, ...}
```

`help` — справка, `exit` — выход. Аргументы передаются как JSON-объект.

```text
model> create_agent {"key": 1, "timestamp": 2000000000}
model> get_agents

model> create_command {"key": 10, "timestamp": 2000000000, "argument": "--help", "agent": 1, "description": "пример", "tags": "demo", "processing": 0}
```
